Technical Perspective

Enterprise Infrastructure & Zero Shadow Users

Clean architectural separation: Data Privacy, PostgreSQL 17 FDW, and Keycloak 26 Identity.

1. IDENTITY TIER

Keycloak 26 (Quarkus)

Enterprise OpenID Connect & OAuth2 identity broker. Uses our custom Java 21 SPI to query master credentials directly with 0 shadow users stored in Keycloak.

2. APPLICATION TIER

Flask & Gunicorn Engine

Single-worker multi-threaded process (-w 1 --threads 8). Guarantees that internal background email and attendance cleanup tasks never double-trigger.

3. DATA TIER

PostgreSQL 17 Multi-DB

Physical separation of users, attendance, and keycloak databases linked inside the engine via postgres_fdw foreign tables.

4. REVERSE PROXY

Nginx 1.24+ SSL

Terminates public HTTPS traffic, injects required forwarded headers, and configures large buffer sizes (128k/256k) to eliminate HTTP 502 SSO cookie truncation.

Federated Single Source of Truth: Passwords are never synced or duplicated. When an employee is deactivated in HR, their access terminates across Web and Android in real time.

Executive Due Diligence

Security & Governance FAQ

Direct answers to technical and operational compliance questions.

Q: Can an employee spoof their GPS with a Fake Location app?

A: No. The Android app checks Android's native location provider flag (isFromMockProvider). Any mock attempt is blocked, rejected by the server, and logged as a tampering flag.

Q: Can a Project Manager alter past attendance to cover for someone?

A: No. In our access control rules (can_edit_attendance), past dates are locked for PMs. Only the authorized System Admin has compliance override privileges.

Q: Does Keycloak duplicate employee passwords in its own database?

A: Zero shadow users. Keycloak connects dynamically via our custom Java 21 SPI directly to your master PostgreSQL database using BCrypt cryptographic hashes.

Q: What happens if an engineer loses internet connectivity on-site?

A: The mobile app cryptographically caches the timestamped punch event locally and synchronizes securely with the server as soon as connection is restored.
